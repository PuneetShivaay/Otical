# 02 — Architecture

> How the code is organised and why. Read before adding files.

## Stack

Next.js 14 (App Router) · JSX only, no TypeScript · Tailwind CSS · Framer Motion · Resend (email) · Vercel

Config files are `.cjs` because `package.json` sets `"type": "module"`.

## Folder structure

```
app/                      Routes only — thin shells, no markup
├── layout.jsx            Fonts, theme script, Navbar, Footer
├── page.jsx              Home — composes sections/
├── work/                 Case studies index + [slug]
├── services/             Index + [service]
└── api/send/route.js     Contact form → Resend

components/
├── ui/                   Primitives. Dumb, reusable, NO business data
│                         Container, Section, SectionHeading, Button, Card, Badge, Reveal
├── sections/             Page sections. Compose ui/, read from data/
│                         Hero, ServicesGrid, ClientMarquee, ProcessTimeline, CTABanner
└── layout/               Navbar, Footer, ThemeToggle

data/                     All content. Plain .js, serializable
├── site.js               Name, tagline, contact details, social links
├── services.js           The 9 services
├── caseStudies.js        Full case studies (3–4)
├── clients.js            All 24 logos
├── team.js               9 members
└── testimonials.js       6 testimonials

docs/                     These documents
public/                   images/{clients,team,testimonials}, logo, og
```

## The three rules

1. **`app/` pages contain no markup** — they only compose `sections/`.
2. **`ui/` never imports from `data/`** — primitives must stay context-free and reusable.
3. **Content never lives in a component** — it lives in `data/`. Components render, data decides.

Rule 3 is what previously broke: `Testimonials.jsx` hardcoded 3 testimonials inline and ignored
the `testimonials` array entirely, and `Navbar.jsx` duplicated its own `navLinks` instead of
using `navItems`. Both caused silent content drift.

## Data conventions

- Data files are **plain `.js`** and fully serializable — **no JSX inside data**.
- Icons are stored as **string names** (`icon: "BotMessageSquare"`) and resolved at render time
  by `components/ui/Icon.jsx`, which maps to `lucide-react`. This keeps data portable
  (a CMS/JSON API could replace it later with no component changes).
- Every entity has a stable **`slug`**; routes resolve by slug, never by array index.

## Routing

| Route | Source |
|-------|--------|
| `/services/[service]` | matches `slug` in `data/services.js`, else `notFound()` |
| `/work/[slug]` | matches `slug` in `data/caseStudies.js`, else `notFound()` |

Adding a service or case study = **adding one object to a data file.** No new component files.

`/projects` is permanently redirected to `/work` in `next.config.mjs` (preserves old inbound links).

## Rendering

Server Components by default. Add `'use client'` **only** for interactivity —
state, event handlers, or Framer Motion. Keep client components as leaf nodes so
page-level JS stays minimal.

## Images

Always `next/image` — never raw `<img>`. It gives automatic sizing, lazy loading and
modern formats, which directly protects LCP/CLS.

> Legacy issue fixed: `Footer.jsx` and `Testimonials.jsx` referenced temporary
> `lh3.googleusercontent.com/aida-...` URLs that would expire and break the page.
> All images must be local under `public/`.

## Contact flow

`ContactForm` validates locally → `POST /api/send` → Resend → `oticalmail@gmail.com`.
The old handler returned **HTTP 200 even on failure**; it must return proper status codes.

## SEO

Every route exports `metadata` (or `generateMetadata` for dynamic routes).
Site-wide defaults + `metadataBase` live in `app/layout.jsx`.
`sitemap.xml` and `robots.txt` are generated by `app/sitemap.js` / `app/robots.js` —
**not** hand-maintained in `public/` (which previously went stale).
